# 实拍照片验证方案（待执行）

本方案用于指导 Windows 首发验证。已用实拍猫咪 JPEG 验证保留原色、项目重开和 PNG 导出的基础行为，并用猫咪及花卉照片检查净化基本运行（见 [样本记录](../tests/fixtures/README.md)）；本方案所需的完整实拍照片测试、Lumina 全流程对照和实物打印尚未完成。已有的程序构造图像测试只能证明特定代码行为，不能证明照片效果。照片测试只采用真实相机拍摄的照片，不采用 AI 生成或程序绘制的照片。简单的几何图形仍可用于验证透明蒙版、坐标和异常边界，且不能冒充照片测试结果。

同一实拍 JPEG 的缩小副本已在本机转换为 JPEG、PNG、WebP、BMP、TIFF、HEIC、HEIF 和 AVIF，并用于自动导入检查；另检验 JPEG EXIF 方向以及带 sRGB 配置的透明 PNG。它们是同一张照片的编码衍生文件，不计作新的拍摄样本，也不能代替不同设备生成的原生文件或色彩准确性验证。

### 原生 HEIC 本机记录

已使用 [libheif 问题 #1190](https://github.com/strukturag/libheif/issues/1190) 中公开的 iPhone 15 Pro / iOS 18 原生照片进行本机 Windows 验证，文件 SHA-256 为 `4b887e6bc345191cbb9836602373b3ec454558ccc62d3518041e085117238fe0`；[样本信息](https://managingwp.github.io/heic-ios18-fix/samples/)列出了设备、校验值和来源。由于照片自身再分发授权尚不明确，原件仅放在本机忽略目录，不纳入本仓库。源代码和本机 PyInstaller 文件夹版均通过离屏 GUI 自动流程，以保留原色模式打开、预览并导出 3024 × 4032 RGBA PNG，孔心和外部角点 alpha 为 0。该样本不能证明 HDR 色彩准确、其他手机兼容、干净 Windows 环境或打印效果。

在同一台 Windows 电脑上，完整 3024 × 4032 照片以默认净化设置处理并导出，单次耗时约 46 秒；过程中观察到工作集峰值至少约 2.19 GB。结果的孔心 alpha 为 0，但尚未据此判断照片细节是否适合打印。时间与内存随硬件、照片和设置而变；需要在更多机器及照片上评估。

取得相同原件后可在 Windows PowerShell 中运行可选回归测试（文件校验值必须匹配）：

```powershell
$env:LPP_REAL_HEIC = 'C:\path\to\original.HEIC'
$env:QT_QPA_PLATFORM = 'offscreen'
python -m unittest discover -s tests -p test_real_heic_optional.py -v
```

设置 `$env:LPP_FULL_HEIC = '1'` 可额外运行原图分辨率的净化测试；该测试比缩小图测试耗时并占用更多内存。

## 样本与来源

建立至少 12 张互不重复的实拍照片，覆盖人像、宠物、风景、花卉或小物件；至少各 2 张包含细毛发、眼睛或五官、小文字或细线、渐变背景、阴影或低光噪声等难点。记录横竖构图和不同分辨率，并检查 EXIF 旋转与嵌入色彩配置。涉及人像须具备展示和使用授权；不确定来源或使用范围的图片不加入公开仓库。

- 至少 3 张为手机或相机直接输出的原始 HEIC/HEIF，覆盖不同方向及色彩配置；注明设备、拍摄来源和原文件的元数据。将 JPEG 转成 HEIC 可用于额外编码兼容性检查，但不能算作相机原生 HEIC 样本。
- 覆盖相机原始 JPEG；从实拍照片转换得到 PNG、WebP、BMP、TIFF、AVIF 可测试格式分支，记录转换方式，不能算成新的独立拍摄样本。透明 PNG 可在实拍照片上加透明蒙版，验证边缘和孔，但要标记为衍生文件。
- 每个样本记录 ID、作者、原始网页或采集方式、许可证和授权范围、原文件 SHA-256、格式、分辨率、方向、ICC、设备和用途。来源不能证实为实拍的样本不入选；不要将项目代码仓库许可证误认为每张图片的授权。
- 优先使用本人拍摄或明确授权的照片；[HEIC EXIF 样本仓库](https://github.com/dsoprea/heic-exif-samples)和 [codec-corpus](https://github.com/imazen/codec-corpus)可作候选线索，逐文件确认拍摄真实性、来源及图片自身的许可证后使用。该 corpus 明确提示部分 HEIC 文件没有明确许可，不应直接打包进公开仓库。
- 私人照片和包含 EXIF 位置等敏感信息的原件只保存在用户本地；公开发布衍生图前单独检查授权和隐私。公开可重现测试优先选允许再分发且许可清晰的图片，提供来源与校验值。

## Windows 测试矩阵

| 维度 | 计划覆盖 | 检查 |
|---|---|---|
| 输入 | 12 张以上实拍照片；原生 HEIC 和 JPEG，以及记录来源的格式衍生文件 | 解码成功、方向正确、色彩配置处理及多图/HDR限制有明确表现 |
| 净化 | 每张图比较不处理、现有默认、优化候选；固定随机条件和版本 | 主体变化、色岛/细线及运行时间；出现破坏性结果可撤销 |
| 几何 | 矩形、圆角矩形、圆形、多边形；有孔和无孔 | 轮廓外和孔内部 alpha=0；半透明抗锯齿边缘合理；孔壁及尺寸提示 |
| 物理尺寸 | 至少 30 mm 和 60 mm 宽；喷嘴 0.2、0.4、0.6 mm | 同一裁切结果的毫米到像素换算正确；不足分辨率有提示 |
| 软件交互 | 中文及长路径、拖放、项目保存重开、撤销、错误文件；源代码及干净 Windows 打包环境 | 不崩溃、不覆盖原图；预览与导出一致；导出的 PNG 正确显示尺寸及透明 |
| 下游 | 固定 Lumina 版本和设置，分别导入原图及处理 PNG | 孔和外轮廓在 Lumina、3MF 和切片中仍正确；记录再次量化影响 |

不必对矩阵做所有组合，但每种格式、尺寸、喷嘴和形状至少覆盖一次，关键照片跨多个尺寸和喷嘴复测。EXIF 方向、颜色配置、HEIC/HDR/多图等样本以实际取得为准，缺样明确标注未验证，不以格式转换代替相机行为。

## 对照和度量

针对 Lumina-Layers 上游提交 `1308c06fc69915e11ead7dbefa0c1e7da11504d0` 的[光栅图像处理代码](https://github.com/lumina-layer-studio/Lumina-Layers/blob/1308c06fc69915e11ead7dbefa0c1e7da11504d0/core/image_processing.py)，高保真路径按 10 px/mm、最近邻缩放，透明像素判断为 alpha 小于 10。项目测试用两张实拍照片、30/60 mm 宽度检查 PNG 经此采样后的孔心、角点及主体透明状态。这是按该版本采样规则做的兼容性检查，并未运行 Lumina、检验轮廓尺寸或生成 3MF；Lumina 的其他版本、模式及材料处理需单独验证。

所有比较保持裁切、成品宽度、喷嘴、材料、Lumina 版本与配置一致；保存原文件、参数、输出 PNG、对应项目和软件版本。原图组采用相同裁切与孔设置但关闭净化；如果当前界面不能真正关闭净化，先补充该基线功能或通过可靠的对照流程实现，不把最低强度当作无处理。

- 报告有色区域的连通色岛数量、低于指定物理面积的色岛数量和面积占比；记录像素密度、连通规则、颜色标签方法和透明边界处理。对 Lumina 输出也尽可能采用相同定义统计，不能跨不同标签定义直接比较。
- 记录像素颜色变化量的分布、处理时间、峰值内存、细节区域变化面积以及误删或异常案例。无标准答案的颜色距离和色岛数量只作为诊断，不能单独宣称画质或可打印性改善。
- 至少两名观察者在同一显示条件下查看匿名前后对照，分别评价主体可辨识性、眼睛/文字/轮廓保真与噪点；保存评价表、分歧和失败示例，阈值待基线确定。
- 输出 PNG 的孔中心及外部远离边缘的区域必须完全透明；几何边界可有半透明抗锯齿像素。DPI 仅供参考，记录并核对 Lumina 中实际设置的毫米尺寸。

## 实物打印与发布门槛

先选择至少两类照片、两种成品宽度；每个喷嘴尺寸至少有一次原图和处理图配对打印。配对件使用相同打印机、喷嘴、耗材批次、层高、速度、切片设置、材料档案和朝向；逐项记录。观察色块边界连续性、孤点、缺失细节、孔贯通及孔壁强度，并拍摄实物照片保存结果。若尚无相应喷嘴或打印设备，记录未覆盖，不以模拟替代实物验证。

Windows 发布须通过以上功能检查、实际 Lumina 导入与配对打印，并完成干净环境打包和依赖许可证核查。尤其应核查所选 pillow-heif 二进制 wheel 包含的编解码库及其分发义务，不能只看 Python 包自身许可证。Mac 开发与打包在 Windows 功能完整且验证通过后启动。
